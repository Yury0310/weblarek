# Интернет-магазин «Web-Larёk»

«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component

Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`

#### Класс Api

Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter

Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` - хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

#### Данные

В приложении используются две сущности, которые описывают данные, — товар и покупатель. Их можно описать такими интерфейсами:

##### Интерфейс товара (IProduct) - для хранения информации о товаре

```
interface IProduct {
  id: string; //идентификатор товара
  description: string; //описание товара
  image: string; //изображение товара
  title: string; //название товара
  category: string; //категория товара
  price: number | null; //цена товара
}
```

##### Интерфейс покупателя (IBuyer) - для хранения информации о покупателе

```
interface IBuyer {
  payment: TPayment; //способ оплаты
  email: string; //email покупателя
  phone: string; //телефон покупателя
  address: string; //адрес покупателя
}
```

#### Модели данных

Для учёта данных в приложении используются три класса:

##### 1. Класс `Catalog`

Отвечает за хранение и управление каталогом товаров, которые доступны для покупки на главной странице приложения.

###### Свойства

| Свойство         | Тип                     | Описание                                                                    |
| :--------------- | :---------------------- | :-------------------------------------------------------------------------- |
| `products`       | `IProduct[]`            | Массив всех доступных товаров в магазине.                                   |
| `currentProduct` | `IProduct \| undefined` | Товар, выбранный пользователем для подробного отображения в модальном окне. |

###### Методы

- `saveProducts(data: IProduct[]): void` — сохранение массива товаров полученного в параметрах метода;
- `saveCurrentProduct(data: IProduct | undefined): void` — сохранение товара для подробного отображения;
- `getProducts(): IProduct[]` — получение массива товаров из модели;
- `getCurrentProduct(): IProduct | undefined` — получение товара для подробного отображения;
- `getProductId(id: string): IProduct|null - получение одного товара по его id.

##### 2. Класс `Basket`

Управляет состоянием корзины: товарами, которые пользователь выбрал для покупки, их количеством и стоимостью.

###### Свойства

| Свойство   | Тип          | Описание                                           |
| :--------- | :----------- | :------------------------------------------------- |
| `products` | `IProduct[]` | Массив товаров, добавленных покупателем в корзину. |

###### Методы

- `addProduct(product: IProduct): void` — добавление товара, который был получен в параметре, в массив корзины;
- `removeProduct(product: IProduct): void` — удаление товара, полученного в параметре из массива корзины;
- `clean(): void` — очистка корзины;
- `getProducts(): IProduct[]` — получение массива товаров, которые находятся в корзине;
- `getTotalPrice(): number` — получение стоимости всех товаров в корзине;
- `getTotalCount(): number` — получение количества товаров в корзине;
- `isProductIn(id: string): boolean` — проверка наличия товара в корзине по его id, полученного в параметр метода.

##### 3. Класс `Buyer`

Отвечает за хранение, управление и валидацию персональных данных покупателя, необходимых для оформления заказа.

###### Свойства

| Свойство  | Тип                | Описание                      |
| :-------- | :----------------- | :---------------------------- |
| `payment` | `TPayment \| null` | Выбранный способ оплаты.      |
| `email`   | `string`           | Электронная почта покупателя. |
| `phone`   | `string`           | Номер телефона для связи.     |
| `address` | `string`           | Адрес доставки заказа.        |

###### Методы

- `savePayment(payment: TPayment): void` - сохраняет выбранный пользователем способ оплаты;
- `saveEmail(email: string): void` - сохраняет введенный email;
- `savePhone(phone: string): void` - cохраняет введенный номер телефона;
- `saveAddress(address: string): void` - Сохраняет адрес доставки;
- `getBuyerData(): BuyerData` - Возвращает объект со всеми собранными данными покупателя;
- `clean(): void` - полностью очищает все сохраненные данные покупателя (сбрасывает их в исходное пустое состояние).
- `validate(): TFormErrors` — проверяет заполненность всех полей покупателя на основе правил валидации. Возвращает объект с ошибками типа `TFormErrors`. Если ошибок нет, возвращается пустой объект `{}`.

##### Слой коммуникации (Взаимодействие с сервером)

Для обмена данными с внешним API сервера «Веб-ларёк» используется класс-AppApi. Класс основан на принципе композиции: он принимает базовый инструмент `Api` в конструктор и использует его методы `get` и `post` для выполнения сетевых запросов.

##### Класс `AppApi`

###### Методы

- `getProducts(): Promise<IProduct[]>`  
  Выполняет `GET`-запрос на эндпоинт `/product/`. Возвращает полный объект ответа от сервера, содержащий общее количество товаров (`total`) и массив объектов товаров (`items`).
- `orderProducts(order: IOrder): Promise<IOrderResult>`  
  Выполняет `POST`-запрос на эндпоинт `/order/`. Передает собранные данные о заказе (способы оплаты, контакты, массив ID купленных товаров). Возвращает объект с подтверждением успешной покупки и итоговой суммой.

  ## Слой Представления (View)

Все классы слоя представления наследуются от базового абстрактного класса `Component`. Они отвечают за отображение интерфейса, управление DOM-элементами и генерацию событий в ответ на действия пользователя.

### 1. Базовые компоненты интерфейса

#### Класс `Modal`

Универсальное модальное окно. Класс является конечным (не может иметь дочерних классов). Служит контейнером для любого другого самостоятельного компонента (например, карточки товара или формы заказа).

- **Конструктор:** `constructor(container: HTMLElement, events: IEvents)` — принимает контейнер модального окна и брокер событий.
- **Свойства:**
  - `protected _closeButton: HTMLButtonElement` — кнопка закрытия модального окна.
  - `protected _content: HTMLElement` — элемент-контейнер для динамического содержимого.
- **Методы:**
  - `open(): void` — открывает модальное окно (добавляет класс активности, вешает слушатели).
  - `close(): void` — закрывает модальное окно (снимает класс активности, очищает контент).
  - `set content(value: HTMLElement): void` — сеттер для вставки разметки компонента внутрь модального окна.
  - `render(data: IModalData): HTMLElement` — переопределяет базовый метод, автоматически открывая окно при рендере контента.

#### Класс `Form<T>`

Абстрактный родительский класс для всех форм на сайте. Инкапсулирует общую логику управления кнопкой отправки и отображения ошибок.

- **Конструктор:** `constructor(container: HTMLFormElement, events: IEvents)` — принимает элемент формы и брокер событий.
- **Свойства:**
  - `protected _submit: HTMLButtonElement` — кнопка отправки формы.
  - `protected _errors: HTMLElement` — элемент для вывода текста ошибок валидации.
- **Методы:**
  - `protected onInputChange(field: keyof T, value: string): void` — внутренний метод, генерирует событие изменения конкретного поля ввода для Презентера.
  - `set valid(value: boolean): void` — сеттер, управляет активностью (разблокировкой) кнопки отправки.
  - `set errors(value: string): void` — сеттер для вывода текста ошибок под формой.
  - `render(state: Partial<T> & IFormState): HTMLFormElement` — обновляет состояние полей формы и возвращает её DOM-элемент.

### 2. Специализированные компоненты форм

#### Класс `OrderForm` (Наследник `Form<IBuyer>`)

Управляет формой выбора способа оплаты и ввода адреса доставки (первый шаг оформления заказа).

- **Свойства:**
  - `protected _cardButton: HTMLButtonElement` — кнопка выбора оплаты "Онлайн".
  - `protected _cashButton: HTMLButtonElement` — кнопка выбора оплаты "При получении".
- **Методы:**
  - `set payment(value: TPayment): void` — сеттер для переключения активного класса на кнопках оплаты.
  - `set address(value: string): void` — сеттер для установки значения в поле адреса.

#### Класс `ContactsForm` (Наследник `Form<IBuyer>`)

Управляет формой ввода контактных данных: email и номера телефона (второй шаг оформления заказа).

- **Методы:**
  - `set email(value: string): void` — сеттер для установки значения в поле почты.
  - `set phone(value: string): void` — сеттер для установки значения в поле телефона.

### 3. Компоненты карточек товаров

#### Абстрактный класс `Card`

Родительский класс для карточек товаров. Содержит общую разметку и логику, которая используется во всех типах карточек на сайте.

- **Конструктор:** `constructor(container: HTMLElement, actions?: ICardActions)` — принимает контейнер карточки и объект с колбэками событий (например, клик по карточке).
- **Свойства:**
  - `protected _title: HTMLElement` — название товара.
  - `protected _price: HTMLElement` — цена товара.
- **Методы / Сеттеры:**
  - `set id(value: string): void`, `get id(): string` — идентификатор товара.
  - `set title(value: string): void` — устанавливает название.
  - `set price(value: number | null): void` — устанавливает цену (если `null`, выводит текст "Бесценно" и блокирует кнопку покупки, если она есть).

#### Класс `CardCatalog` (Наследник `Card`)

Отображает карточку товара в главном каталоге на главной странице сайта.

- **Свойства:**
  - `protected _image: HTMLImageElement` — изображение товара.
  - `protected _category: HTMLElement` — тег категории товара (софт-скиллы, хард-скиллы и т.д.).
- **Методы / Сеттеры:**
  - `set image(value: string): void` — устанавливает ссылку на картинку.
  - `set category(value: string): void` — устанавливает текст категории и задает ей соответствующий CSS-класс цвета.

#### Класс `CardPreview` (Наследник `CardCatalog`)

Расширяет карточку каталога для подробного отображения товара внутри модального окна.

- **Свойства:**
  - `protected _description: HTMLElement` — подробное описание товара.
  - `protected _button: HTMLButtonElement` — кнопка «В корзину» / «Удалить из корзины».
- **Методы / Сеттеры:**
  - `set description(value: string): void` — устанавливает текст описания.
  - `set buttonText(value: string): void` — меняет текст на кнопке в зависимости от того, находится ли товар в корзине.

#### Класс `CardBasket` (Наследник `Card`)

Отображает компактную строку товара внутри корзины.

- **Свойства:**
  - `protected _index: HTMLElement` — порядковый номер товара в списке корзины.
  - `protected _button: HTMLButtonElement` — кнопка удаления товара (иконка корзины).
- **Методы / Сеттеры:**
  - `set index(value: number): void` — устанавливает порядковый номер строки.

### 4. Общие компоненты страницы

#### Класс `Page`

Управляет корневыми элементами всей главной страницы (счетчик корзины, обертка каталога и блокировка прокрутки).

- **Свойства:**
  - `protected _counter: HTMLElement` — элемент цифры-счетчика на кнопке корзины.
  - `protected _catalog: HTMLElement` — контейнер-сетка, куда вставляются карточки товаров.
  - `protected _wrapper: HTMLElement` — главная обертка страницы (для блокировки скролла при открытой модалке).
  - `protected _basketButton: HTMLButtonElement` — кнопка корзины в шапке сайта.
- **Методы / Сеттеры:**
  - `set counter(value: number): void` — обновляет число на иконке корзины.
  - `set catalog(items: HTMLElement[]): void` — полностью перезаполняет сетку каталога готовыми DOM-элементами карточек.
  - `set locked(value: boolean): void` — включает/выключает класс блокировки прокрутки страницы.

## События приложения

В приложении используется брокер событий (`EventEmitter`) для связи слоев данных (Model) и представления (View).

| Имя события       | Источник (Компонент)                    | Описание                                                                                 |
| :---------------- | :-------------------------------------- | :--------------------------------------------------------------------------------------- |
| `items:changed`   | Модель `Catalog`                        | Каталог товаров обновился (загружен с сервера). Страница перерисовывает сетку карточек.  |
| `card:select`     | Компонент `CardCatalog`                 | Пользователь кликнул на карточку в галерее. Открывается модальное окно просмотра товара. |
| `card:buy`        | Компонент `CardPreview`                 | Пользователь кликнул на кнопку покупки в окне товара. Товар добавляется в корзину.       |
| `card:remove`     | Компоненты `CardPreview` / `CardBasket` | Пользователь удалил товар из корзины. Сумма и список товаров пересчитываются.            |
| `basket:open`     | Компонент `Page`                        | Клик по иконке корзины в шапке сайта. Открывается модалка со списком покупок.            |
| `order:open`      | Компонент `BasketView`                  | Клик по кнопке «Оформить» в корзине. Открывается первый шаг формы заказа (оплата/адрес). |
| `payment:change`  | Компонент `OrderForm`                   | Изменился выбранный способ оплаты. Переключается активный класс кнопок.                  |
| `order:input`     | Компоненты `OrderForm` / `ContactsForm` | Пользователь вводит текст в инпуты. Запускается валидация измененных полей.              |
| `order:submit`    | Компонент `OrderForm`                   | Клик по кнопке «Далее» в форме адреса. Открывается форма контактов.                      |
| `contacts:submit` | Компонент `ContactsForm`                | Клик по кнопке «Оплатить». Начинается процесс отправки заказа на сервер.                 |

## Слой Презентера

Слой презентера отвечает за бизнес-логику приложения, синхронизацию данных из моделей со слоем представления (View) и обработку действий пользователя.

В приложении используется подход, при котором роль Презентера выполняет основной скрипт **`main.ts`**. Код презентера представляет собой набор слушателей брокера событий (`EventEmitter`). При наступлении какого-либо события (изменение данных в модели или клик пользователя в интерфейсе), презентер перехватывает его, вносит изменения в соответствующие модели или вызывает методы рендеринга у компонентов представления.
Такой подход избавляет от необходимости создавать громоздкие классы-контроллеры и делает логику единственной страницы приложения линейной и легко читаемой.
